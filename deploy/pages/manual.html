Cellar Guard / User manual

Protect CSV imports. On every PR.

Start with a safe example. See a CSV pass, watch a renamed column block the release, fix that column, and check again. The real Java checker runs on your computer; this page explains the steps.

Open CSV checkerDownload Windows app (.exe)See the fix demo

Check a CSV in your browser.

Use the same page on a phone, tablet or computer. Your selected files stay on your device.

  1. Open the CSV checker. Select Load breaking example to run it immediately.
  2. Open the failing integration to see the missing order_id column. Load the passing example to see the difference.
  3. Type one required column per line under Import rules. Choose the delimiter and tap Use these rules, then select your CSV or paste its text. If you already have a contract, open Import or edit JSON.
  4. The check starts once both files are ready. After editing pasted text, select Check export. Use Download report to save the findings.
  5. On a phone, use the shortcuts to jump between rules, the CSV, and the check. Select Remember these rules on this device before applying them to reuse the column names next time. Tap Get help to find answers or ask the team.

01 / Download & run

Open the desktop checker.

Windows x64: Double-click Cellar-Guard-Windows-x64.exe. It includes Java and opens the desktop checker. Use Run breaking demo, Apply demo fix & recheck, and User manual for a walkthrough.

Java workspace and CLI: Download the Java ZIP and extract it. Install Java 21 or newer, then run sh start-guard.sh on macOS/Linux or double-click start-guard.bat on Windows. Open the local address printed in the terminal.

02 / Demonstration

PASS. BLOCK. PASS again.

All three CSVs in the ZIP are synthetic. Run try-demo.bat on Windows or sh try-demo.sh on macOS/Linux to see the actual Java report.

PASS / Exit 0

Original export

order_id,sku,total_cents,currency

The consumer contract expects order_id, and it exists.

BLOCK / Exit 1

Breaking export

id,sku,total_cents,currency

Someone renamed order_id to id. The customer's importer may fail.

FIXED / Exit 0

Compatible export

order_id,sku,total_cents,currency

Restore the required header, or provide both columns during a coordinated migration.

The checker reports which integration failed, the exact missing column, and Gate: BLOCK. It does not automatically rewrite production data.

03 / Fix it yourself

Repair the broken header.

A simple practice exercise you can complete in Notepad or VS Code.

  1. Copy samples/broken.csv to samples/my-repair.csv.
  2. Open the copy in a text editor. Change the first header from id to order_id.
  3. Save, then run the command below inside the extracted release folder.
  4. Look for Gate: ALLOW. You repaired the sample!
java -jar cellar-guard.jar check --config contracts/example-contract.json --csv samples/my-repair.csv

Important: In a real app, fix the export-producing code too. Editing one CSV will not prevent next week's bad export. Keep the original column until the customer has migrated.

04 / Use your own CSV

Define the customer promise.

Make a copy of the sample contract, change required columns and rules to match the customer's importer, and run the checker on your own freshly generated CSV.

java -jar cellar-guard.jar check --config contracts/my-contract.json --csv path/to/my-export.csv

Use uniqueKeys to catch duplicates across a combination of columns, such as order_id and item_id. Set "validateRows": true to check record structure with a header-only contract.

Exit 0: declared rules passed. Exit 1: a breaking rule failed. Exit 2: the check could not run; nothing was verified. Never change a contract just to hide an incompatibility.

05 / Pull requests

Run the check before merge.

The repository includes .github/workflows/guard-pr.yml. GitHub Actions executes it on every pull request to main.

Step 1

Generate the export.

Replace the workflow’s example CSV path with a representative CSV generated from the proposed application code.

Step 2

Review contracts.

Commit consumer expectations under version control. A checker cannot infer hidden customer requirements.

Step 3

Require the check.

In repository branch protection, require the Cellar Guard / csv-compatibility check before merging.

The included workflow checks the tracked synthetic CSV until you wire it to your application’s export command. For the complete configuration, report formats, troubleshooting and security boundaries, see the technical manual.
